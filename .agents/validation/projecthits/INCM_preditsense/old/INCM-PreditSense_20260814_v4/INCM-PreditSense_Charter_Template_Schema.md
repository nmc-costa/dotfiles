## [section_17] Políticas Básicas de Governação – Recomendações Básicas para facilitar uma comunicação eficiente entre os parceiros, reduzir conflitos e estabelecer as responsabilidades de ambas as partes.

**Classification:** RIGID (Heading Structure)


```
[REGENERATE - Paragraph]
Project Charter: deve ser formalmente aprovado através da assinatura dos principais representantes das entidades envolvidas. A aprovação do Project Charter determina que ambas as partes concordam plenamente com todo o conteúdo expresso no documento assinado por eles.
```


```
[REGENERATE - Paragraph]
Steering Committee: composto pelos Diretores do Projeto, tem como objetivo garantir o acordo comum e alinhamento estratégico entre as partes envolvidas no Projeto e também resolver disputas
```


```
[REGENERATE - Paragraph]
Reuniões Técnicas: agendadas pelo Coordenador Técnico do Projeto do DTx, e realizadas todas as semanas com toda a equipa de desenvolvimento no contexto das Atividades/Tarefas Técnicas ativas no momento. Nestas reuniões, são apresentados e discutidos os últimos desenvolvimentos técnicos, juntamente com as principais dificuldades e problemas enfrentados por cada membro da equipa, futuros desenvolvimentos planeados e riscos identificados e possíveis respostas aos riscos. É encorajada a participação de um representante do Associado pelo menos uma vez por mês para garantir o alinhamento do projeto e uma transferência de conhecimento bem-sucedida.
```


```
[REGENERATE - Paragraph]
Reuniões e Relatórios de Project Status: estas reuniões são agendadas pelo PMO do DTx e são realizadas mensalmente até que o projeto seja concluído como parte da Atividade de Gestão de Projetos. Pelo menos um representante da equipa do Associado deve participar destas reuniões. O objetivo das reuniões de estado é acompanhar o progresso das atividades do projeto com base em: (1) uma visão geral breve: um resumo dos desenvolvimentos alcançados durante o período, incluindo o estado dos objetivos, resultados, evolução de funcionalidades inovadoras, entregáveis e marcos; (2) cronograma do projeto e horas gastas: análise do cronograma do projeto e do tempo alocado, identificação de desvios que possam potencialmente afetar o progresso do projeto, e planeamento de ações para garantir que os requisitos do projeto sejam cumpridos; (3) gestão de riscos: ações tomadas para abordar riscos inesperados que surjam durante a execução do projeto; (4) gestão de problemas: ações tomadas para abordar quaisquer elementos que já estejam afetando o desempenho do projeto; (5) descrição e planeamento de futuros desenvolvimentos: discussão e planeamento das atividades esperadas para o período seguinte; e (6) outros tópicos relevantes: quaisquer assuntos adicionais que precisem ser discutidos durante a reunião. Estas reuniões serão conduzidas pela Coordenação do DTx. Um relatório será gerado após cada reunião de estado. No entanto, para adotar uma abordagem mais ágil, pode haver casos em que a reunião seja substituída por um relatório analisando o período correspondente. Esta substituição pode ocorrer apenas se não houver questões ou preocupações especiais a serem discutidas sobre o progresso do projeto. O relatório será enviado à Coordenação do Projeto do Associado por e-mail. É recomendado seguir este formato ágil, com reuniões sendo substituídas por relatórios, no mínimo uma vez a cada dois meses. Além disso, se as circunstâncias se alinharem, estas reuniões também podem ser substituídas por uma reunião do Steering Committee.
```


```
[REGENERATE - Paragraph]
Reuniões e Relatórios de Steering Committee: estas reuniões são agendadas pelo PMO do DTx, o SC se reunirá formalmente com os Coordenadores Técnicos do Projeto e PMOs, estas reuniões são realizadas no contexto da Atividade de Gestão de Projetos. Serão realizadas bimestralmente ou sempre que o projeto tiver alguma entrega relevante que exija aprovação formal para poder avançar para a próxima etapa de desenvolvimento, até a conclusão do Projeto. De cada reunião resultará um relatório que deve ser validado pelo SC dentro de uma semana, após o que o conteúdo de cada relatório será considerado automaticamente validado e aprovado pelo Steering Committee. Entre os elementos constituintes (Diretores do Projeto), o SC deve se reunir sempre que houver um desacordo crítico, decisão, problema ou risco a ser discutido e decidido. A reunião do SC será conduzida pelo DTx.
```


```
[REGENERATE - Paragraph]
Gestão de Alterações: qualquer alteração solicitada deve ser formalmente justificada, analisada e discutida; esta análise deve compreender o impacto nos resultados e sua qualidade, na alocação de horas, no tempo e no cronograma, novos riscos e questões, etc. Esta análise deve ser apresentada, negociada e aprovada pelas entidades envolvidas. Uma vez aprovada, deve ser refletida em uma nova versão da carta do projeto, não negligenciando refletir cada justificação e documentar cada alteração para evitar futuros desentendimentos ou mal-entendidos. Esta nova versão deve ser formalmente assinada pelos representantes.
```


```
[REGENERATE - Paragraph]
Fecho e Aceitação do Projeto: Se o projeto atender a todos os requisitos definidos na secção 3, o Associado deve aceitar o resultado do projeto. Esta aceitação também deve ser comunicada formalmente pelo Associado ao representante do DTx. Para garantir isso, uma reunião de encerramento formal será realizada.
```
