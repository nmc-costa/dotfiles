Proposal: Reorganize tasks/ directory to keep an explicit "current" surface small

Goal
- Keep the top-level tasks/ directory focused on scripts and a small set of live views.
- Move larger/generated/browsing history and less-frequently-edited items into subdirectories to reduce cognitive load and session context size.

Principles
- Generated views remain generated, never hand-edited.
- Generators must accept an output directory via env var (TASKS_OUTPUT_DIR) or default to tasks/ for backward compatibility.
- No data loss: events.jsonl stays in place as the single append-only source of truth.
- Migration steps are scripted and reversible.

Proposed layout

tasks/
├── events.jsonl                # single append-only log (unchanged)
├── claims.jsonl                # append-only
├── .events.lock
├── scripts/                    # rewrite of top-level .py utilities
│   ├── append_event.py
│   ├── dispatch.py
│   └── ...                     # other CLI tools
├── generators/                 # generators and rebuild_* scripts
│   ├── rebuild_kanban.py
│   ├── rebuild_cards.py
│   └── rebuild_graph.py
├── generated/                  # generated views (git-tracked, generated by scripts)
│   ├── kanban.md
│   ├── cards/                  # per-task card files
│   ├── archive.md
│   └── roadmap.md
├── proposals/                  # design proposals & migration plans
│   └── reorg.md
├── evaluations/                # kept as-is (smaller files)
└── helpers/                    # helper modules (paths.py, lifecycle.py)

Notes
- Generators should be updated to accept TASKS_OUTPUT_DIR. Current scripts should keep their defaults to preserve behavior.
- The "generated/" folder is git-tracked but regenerated. Keep a README explaining regeneration commands: `python3 generators/rebuild_kanban.py && python3 generators/rebuild_cards.py`.

Migration plan (safe, reversible)
1. Create generators/ and scripts/ directories and move copies of the existing top-level scripts there.
2. Update shebangs and module imports if paths change (use tasks.paths.tasks_root() where needed).
3. Update generators to accept TASKS_OUTPUT_DIR (already implemented for rebuild_kanban.py).
4. Create generated/ and run generators with TASKS_OUTPUT_DIR=generated.
5. Verify consumers (tuiboard, CI) still read tasks/kanban.md — if any depend on the old path, either update them or leave a shallow symlink at tasks/kanban.md pointing to generated/kanban.md.
6. Commit changes in a single PR.

Backward compatibility
- By default generators write to tasks/ for now. Once consumers are updated, change defaults to generated/.
